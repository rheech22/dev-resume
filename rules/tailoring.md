# 공고 맞춤본

맞춤본은 기본 이력서의 사본으로 만듭니다. 기본 이력서를 공고에 맞춰 직접 고치지 않습니다.

## 1. 공고 분석

공고 원문을 `<home>/jobs/<회사>.md`에 저장하고 다음을 뽑습니다.

- **직무 정의**: 공고가 이 직무에 기대하는 일. 예: "기획부터 배포, 운영 지표까지 한 기능을 끝까지 책임".
- **요구 역량**: 명시된 역량과 우대 사항. 경력 연수 기준도 포함합니다.
- **기술 스택**: 공고가 쓰는 스택과 "두려워하지 않을 것"을 요구하는 스택을 구분합니다.
- **문화 신호**: 자율, 주도, 창업자 모드, 실험 같은 일하는 방식.

## 2. 역량 대응표

요구 역량마다 `facts`에서 근거를 찾아 대응표를 만듭니다.

| 요구 역량 | 근거 (facts) | 강도 | 이력서 위치 |
| --- | --- | --- | --- |
| 운영 지표까지 책임 | 결제 실패율 대시보드와 알림 구축 | 강 | 프로젝트 1, 불릿 3 |
| 서버 개발 | API 스키마 리뷰 참여 | 약 | 소개 단락 |

- **강**: 결과까지 있는 근거. 맞춤본의 앞쪽으로 올립니다.
- **약**: 관련은 있지만 직접 경험이 아닌 근거. 부풀리지 않고 정확한 범위로 씁니다. 공백은 면접 메모에 대비 답변을 적습니다.
- **없음**: 근거가 없는 역량. 이력서에 쓰지 않습니다.

## 3. 사본 편집

- **헤드라인**을 공고의 직무명에 맞춥니다.
- **공고의 표현**이 사실 범위 안에서 맞으면 그 표현을 문장에 씁니다. 공고 키워드를 따로 나열하지 않습니다.
- **핵심 역량의 순서**를 대응표의 강도 순으로 바꿉니다.
- **프로젝트 안 소제목의 순서**를 공고가 중시하는 순서로 바꿉니다.
- **2페이지로 줄입니다.** 아래 순서로 줄이고, 줄일 때마다 렌더해서 분량을 확인합니다.
  1. 공고와 관련이 낮은 사이드 프로젝트의 설명
  2. 결과 불릿을 보충하는 구현 세부 불릿 (한 줄로 압축하거나 삭제)
  3. 교육 항목의 설명
  4. 공고와 관련이 낮은 오래된 경력의 기능 나열 불릿
  5. 비슷한 성격의 작은 프로젝트끼리 합치기

## 4. 지원 동기와 짧은 커버레터

공고가 요구하거나 사용자가 원할 때만 씁니다.

- 공고의 문장 하나와 `facts`의 경험 하나를 연결합니다. 회사 칭찬으로 시작하지 않습니다.
- 3~5문장으로 씁니다.
- 사용자가 직접 한 말 중에 태도를 보여 주는 문장이 있으면 그 표현을 살립니다. 문장을 지어내지 않습니다.

## 5. 면접 메모

리뷰에서 나온 예상 질문, 숫자의 측정 조건, 공백 역량에 대한 대비 답변을 `<home>/jobs/<회사>-notes.md`에 남깁니다. 이력서 도구가 인쇄되지 않는 메모 칸을 제공하면 그곳에도 둘 수 있습니다.
