# 한국어 표기와 교열

## 문체

- 불릿과 소개 단락은 개조식 명사형으로 끝냅니다. `~구축`, `~해결`, `~전환`. `~했습니다`, `~함`과 섞지 않습니다.
- 한 문장에 주장 하나를 둡니다. 쉼표로 이어진 행동이 셋을 넘으면 문장을 나눕니다.
- 주체가 본인이 아닌 일은 주어를 밝힙니다. `백엔드는 별도 팀이 담당하고, …`.
- 불릿은 확정된 결과로 끝냅니다. `~추적 중`, `~예정`처럼 진행형으로 끝나는 내용은 면접 메모로 옮깁니다.
- "참여", "기여", "지원"은 실제로 한 일을 가리면 구체적인 동사로 바꿉니다. 실제 역할이 그 정도면 그대로 둡니다. 부풀리는 것보다 정확한 것이 면접에서 안전합니다.

## 표기 통일

한 이력서 안에서 같은 개념은 한 가지로 씁니다. 아래는 기본값이며, 사용자가 다른 표기를 정하면 그것을 따릅니다.

| 쓰는 표기 | 쓰지 않는 표기 |
| --- | --- |
| 스킬 | skill, Skill |
| 폴백 | fallback |
| 프로덕션 | production |
| 서버 액션 | server action (프레임워크 고유 API 이름을 쓸 때는 원어) |
| 폴링 | Polling |
| Google Sheets | 구글 시트 |
| `A·B` (가운뎃점) | `A 및 B`, `A, B 및 C` |
| `2025–` (기간) | `2025~` |
| 작업 시, 결정 사항 | 작업시, 결정사항 |

- 정착된 기술 고유명사, 제품 이름, API 이름은 원어로 씁니다. `GitHub Actions workflow_dispatch`, `WebSocket`.
- 같은 문서의 다른 고유명사가 영문이면 서비스 이름도 영문으로 맞춥니다.

## 자주 나오는 오류

검수할 때 아래를 직접 찾습니다. `scripts/check-copy.mjs`가 일부를 기계로 찾습니다.

| 오류 | 예 | 고침 |
| --- | --- | --- |
| 공백 두 칸 | `운영.  2026년` | 한 칸 |
| 조사·어미 누락 | `줄이기 React Native에서` | `줄이기 위해 React Native에서` |
| 굵은 글씨 안의 콜론 | `**리드:**` | `**리드**:` |
| 리드와 본문의 주제 불일치 | 리드는 검사, 본문은 구축 | 리드를 본문에 맞추거나 불릿을 나눔 |
| 같은 말 반복 | `화면 버벅임 개선, … 해결. … 개선` | 동사 하나로 정리 |
| 번역투 | `문서를 그대로 투영하되 사람이 읽기 좋은` | `문서를 사람이 읽기 좋게 보여 주는` |
| 주어가 어색한 끝맺음 | `…작성해 새 팀으로 이동` | `…작성해 넘긴 뒤 새 팀으로 이동` |
| 근거 없는 수식어 | `매우`, `다양한`, `성공적으로`, `획기적으로` | 삭제하거나 사실로 바꿈 |
| 자기 평가 | `마찰 없이`, `완벽하게` | 한 일로 바꿈 |
