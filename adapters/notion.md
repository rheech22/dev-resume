# notion

이력서를 Notion 페이지로 관리하는 경우입니다.

> 이 adapter는 Notion 공식 API 문서를 바탕으로 썼고, 실제 이력서 페이지에서 검증하지 않았습니다. 쓰면서 다른 동작을 발견하면 이 문서를 고쳐 주세요.

## 연결 확인

Notion MCP나 API로 접근합니다. 편집하기 전에 연결된 워크스페이스와 계정을 확인하고 사용자에게 보여 줍니다.

- 회사 워크스페이스에 연결되어 있으면 이력서 작업을 하지 않습니다. 이직 준비 자료가 회사 워크스페이스에 남고, 관리자가 볼 수 있습니다.
- 연결된 계정이 사용자 본인이 아니면 작업하지 않고 사용자에게 알립니다.

## 읽기

- 이력서 페이지를 블록 단위로 읽습니다. 제목, 단락, 불릿, 토글, 콜아웃, 컬럼, 표, 하위 페이지, 데이터베이스가 섞여 있을 수 있습니다.
- 토글 안의 블록과 하위 페이지는 기본으로 펼쳐 읽히지 않을 수 있습니다. 자식 블록까지 읽었는지 확인합니다.
- 데이터베이스로 프로젝트를 정리한 이력서는 각 행의 속성과 본문을 함께 읽습니다.

## 편집

- 편집 직전에 대상 블록을 다시 읽습니다. 사용자가 Notion에서 직접 고쳤을 수 있습니다.
- 페이지 전체를 새로 쓰지 않고, 바꿀 블록의 텍스트만 바꿉니다. 페이지를 통째로 바꾸면 토글, 컬럼, 콜아웃 같은 구조와 블록 ID가 바뀔 수 있습니다.
- 블록의 텍스트는 서식(굵게, 기울임, 코드, 색)과 링크가 붙은 조각들의 배열입니다. 문장을 바꿀 때 기존 조각의 서식과 링크를 다시 붙입니다. 문자열 하나로 덮어쓰면 굵은 리드와 링크가 사라집니다.
- 큰 변경 전에는 페이지를 복제해 백업합니다. Notion 페이지 기록도 있지만 보관 기간이 요금제에 따라 다릅니다.

## 공개 상태

이력서 페이지를 웹에 공개해 링크로 제출하는 경우가 많습니다.

- 편집 전에 페이지가 공개되어 있는지 확인합니다. 공개 페이지라면 고친 내용이 바로 외부에 보인다고 사용자에게 알립니다.
- 공고 맞춤본은 페이지를 복제해서 만들고, 공개 여부는 사용자가 정합니다.

## 디자인

Notion은 모양을 바꿀 수 있는 범위가 좁습니다. `design`을 기록할 때 이 범위 안에서만 제안합니다.

| 바꿀 수 있는 것 | 바꿀 수 없는 것 |
| --- | --- |
| 블록 종류(제목 단계, 불릿, 토글, 콜아웃, 구분선), 컬럼 블록, 글자색과 배경색, 페이지 폰트 세 가지(기본, 세리프, 모노), 작은 글씨, 전체 너비 | 임의의 폰트, 글자 크기와 줄 간격의 세부 값, 여백, PDF의 페이지 넘김 위치 |

- 토글 안의 내용은 PDF 내보내기와 인쇄에서 접힌 채 빠질 수 있습니다. 제출할 내용은 토글 밖에 둡니다.
- 컬럼 블록은 좁은 화면에서 세로로 쌓입니다. 공개 링크로 제출하면 모바일 너비에서 순서를 확인합니다.
- 위 범위는 API 문서 기준이며 실제 페이지에서 검증하지 않았습니다.

## 렌더 점검

제출 방식에 따라 점검 대상이 다릅니다. 처음 실행에서 어떻게 제출하는지 묻고 workspace의 `render`에 적습니다.

| 제출 방식 | 점검 대상 |
| --- | --- |
| 공개 링크 | 웹 화면. 데스크톱과 모바일 너비에서 각각 봅니다. 페이지 경계 대신 첫 화면에 무엇이 보이는지를 봅니다 |
| PDF 내보내기 | 내보낸 PDF. Notion 화면과 다르게 나올 수 있으니 PDF 자체를 봅니다. 이후 점검은 `adapters/pdf.md`의 렌더 점검을 따릅니다 |

## 교열 검사

페이지 내용을 마크다운으로 받아 `scripts/check-copy.mjs`를 돌립니다. 굵게 표시는 `**`로 남아야 콜론 위치 검사가 동작합니다.
