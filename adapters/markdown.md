# markdown

이력서 원본이 마크다운 파일인 경우입니다. 기본 형식입니다.

## 편집

- 편집 직전에 파일을 다시 읽습니다. 사용자가 편집기에서 고쳤을 수 있습니다.
- 바꿀 문장만 바꿉니다. 파일 전체를 다시 쓰지 않습니다.
- 저장소로 관리하면 큰 변경 전에 커밋을 남깁니다. 아니면 `<home>/versions/`에 날짜를 붙인 사본을 둡니다.

## 구조 관례

```markdown
# 이름
헤드라인
이메일 · 전화 · [GitHub](https://github.com/...)

## 핵심 역량
- **결과 리드**: 본문

## 경력
### 회사명 (2023.03 – 현재)
직함 · 위치
- 담당 범위 한 줄

## 프로젝트 · 회사명
### 프로젝트 이름 (2025.12 – 현재)
소개 한 단락
[서비스](https://...) · [App Store](https://...)

**소제목**
- **결과 리드**: 본문
  - 하위 불릿

## 학력
### 학교 또는 과정 이름 (2017.03 – 2021.02)
학위 · 전공
```

- `#` 바로 아래, 빈 줄 없이 이어지는 줄은 모두 연락처 줄로 한 줄씩 보입니다.
- `###` 끝의 괄호는 날짜 모양(연도, `03/2025`, `2025.03`, 현재, Present)이면 오른쪽에 기간으로 붙습니다. `(iOS 17 대응)` 같은 괄호는 제목에 남습니다.
- 회사명 옆에 위치와 기간을 둘 다 오른쪽에 둘 수는 없습니다. 위치는 직함 줄로 내립니다.
- 굵은 글씨만 있는 줄과 `####`는 소제목입니다.
- 렌더러가 다루는 문법: 제목(`#`~`####`), 단락, 불릿(`-`, `*`, `+`), 번호 목록, 들여쓴 하위 목록, 굵게, 기울임, 코드, 링크, 꺾쇠 링크, 맨 URL과 이메일, 역슬래시 이스케이프. 표, 이미지, 인용, 각주는 다루지 않고 글자 그대로 나옵니다.
- 단락 안의 줄바꿈은 공백 하나가 됩니다. 한국어 문장은 줄을 나누지 말고 한 줄로 씁니다.

## 디자인

마크다운에는 모양이 없습니다. 모양은 PDF로 바꾸는 도구의 스타일 파일이 정합니다.

- 기본 렌더러(아래 "렌더")의 모양은 `templates/resume.css`입니다. A4, 단일 컬럼, 산세리프, 강조색 하나로 된 무난한 모양이며, 정답이 아니라 출발점입니다.
- 모양을 바꾸려면 `templates/resume.css`를 `<home>/style.css`로 복사해 고치고 `--css`로 넘깁니다. skill 폴더의 CSS는 고치지 않습니다.
- `design`을 바꾸면 이력서 본문이 아니라 스타일 파일을 고칩니다. CSS로 바꿀 수 있는 것은 거의 모두 바꿀 수 있습니다: 폰트, 크기, 색, 여백, 컬럼, 페이지 넘김.
- 폰트를 바꾸면 PDF 텍스트 추출을 다시 확인합니다. 같은 화면이라도 폰트에 따라 추출한 단어가 중간에서 끊길 수 있습니다(예: macOS의 Apple SD Gothic Neo). 기본 CSS는 이 때문에 나눔바른고딕을 앞에 둡니다.
- 2단·사이드바처럼 마크다운 구조로 표현하기 어려운 모양은 HTML을 직접 고치지 않습니다. 사용자에게 다른 도구를 쓰거나 1단 안에서 비슷한 효과를 내는 방법을 제안합니다.

## 렌더

기본 렌더러는 `scripts/render.mjs`입니다. 의존성 없이 Node와 설치된 Chrome 계열 브라우저(Chrome, Edge, Chromium, Brave)만 씁니다.

```bash
node <skill>/scripts/render.mjs <home>/resume.md                          # resume.html, resume.pdf
node <skill>/scripts/render.mjs <home>/resume.md --css <home>/style.css   # 사용자 스타일
node <skill>/scripts/render.mjs <home>/resume.md --html-only              # 브라우저가 없을 때
```

`<skill>`은 이 skill이 설치된 폴더입니다. workspace의 `render`에는 두 경로를 절대 경로로 적어서 어느 위치에서 실행해도 같은 결과가 나오게 합니다.

- "구조 관례"를 따른 마크다운을 그대로 읽습니다. 소제목 끝의 괄호에 숫자가 있으면 기간으로 오른쪽에 붙이고, 굵은 글씨만 있는 줄은 소제목으로 봅니다. 표와 이미지는 다루지 않습니다.
- 브라우저를 찾지 못하면 HTML만 만들고 멈춥니다. 사용자에게 HTML을 브라우저에서 열어 인쇄 → PDF로 저장하라고 안내하거나, 경로를 `CHROME_PATH`로 받습니다.
- 사용자가 pandoc, 문서 편집기 같은 다른 도구를 쓰고 싶어 하면 그 방법을 workspace의 `render`에 적고 따릅니다.
- PDF를 만든 뒤에는 `adapters/pdf.md`의 렌더 점검으로 페이지 이미지와 텍스트를 확인합니다.
