# dev-resume

저장소와 커밋을 근거로 개발자 이력서를 쓰고, 여러 면접관 관점으로 검증하는 agent skill입니다.
한국어 이력서와 경력기술서를 대상으로 합니다.

이력서에 들어가는 숫자, 원인, 결과, 본인 몫을 코드와 문서에서 확인하고, 확인할 수 없는 사실은 지어내지 않고 사용자에게 묻습니다.
완성된 이력서는 서로 다른 관점의 리뷰어가 독립적으로 읽고, 그 결과를 검증해서 사용자가 판단할 수 있게 정리합니다.

## 설치

AI에게 맡기려면 이 저장소를 clone하게 하고 [SETUP.md](SETUP.md)를 따르게 하세요. 설치 위치와 개인 자료를 둘 경로를 정해 줍니다.

직접 설치하려면 쓰는 agent가 skill을 읽는 경로에 두면 됩니다.

```bash
git clone https://github.com/rheech22/dev-resume.git <skill 경로>/dev-resume
```

## 사용

파일을 직접 고칠 일은 없습니다. 모든 것을 대화로 합니다.

처음에는 지금 쓰는 이력서를 건네면 됩니다. 형식은 PDF, docx, 마크다운, URL 무엇이든 괜찮습니다.

관리 방식별로 읽기·편집·렌더 요령을 담은 adapter가 있습니다: 마크다운(기본), PDF, Notion, Reactive Resume. 맞는 adapter가 없으면 agent가 편집 방법을 묻고 기록합니다.

```text
지금 쓰는 이력서야. 이걸로 시작하자.
```

agent는 이력서를 사실 단위로 쪼개 경력 사실 파일에 기록하고, 이력서로 읽히는 커리어 방향을 추정해 확인을 받습니다.
지금 이력서와 다른 방향으로 가고 싶다면 그때 말하면 됩니다. 근거로 볼 수 있는 자료가 있으면 알려 주세요. 저장소, 문서, 메신저 대화, 이메일, 파일, 화면 캡처 무엇이든 됩니다. 기존 이력서의 숫자와 주장을 자료와 대조합니다.

그다음은 원하는 일을 말하면 됩니다.

```text
프로덕트 엔지니어 쪽으로 방향을 잡고 싶어. 핵심 역량부터 다시 써줘.
이 공고에 맞춘 2페이지짜리 사본 만들어줘. (공고 첨부)
면접관 관점으로 리뷰해줘. 이 글을 쓴 사람 관점도 추가해줘. (링크)
렌더된 PDF에서 페이지 경계 좀 봐줘.
이 숫자는 틀렸어. 120건이 아니라 90건이야.
```

| 모드 | 하는 일 |
| --- | --- |
| `intake` | 기존 이력서를 사실로 쪼개고, 커리어 방향과 공고를 받아 기록합니다 |
| `write` | 경력 사실과 커리어 방향을 바탕으로 문장을 쓰거나 고칩니다 |
| `review` | 리뷰어 3명(채용 결정권자, 회의적인 시니어, 채용 담당자·교열자)이 독립적으로 읽습니다. 리뷰어는 바꾸거나 더할 수 있습니다 |
| `tailor` | 공고를 분석해 역량 대응표를 만들고, 공고에 맞춘 사본을 만듭니다 |
| `layout` | 렌더된 PDF에서 페이지 경계, 잘린 항목, 빈 공간, 시각 위계를 점검합니다 |

설정과 기록은 skill 폴더 밖의 `home`(기본 `~/resume/`)에 쌓입니다. 설정, 경력 사실, 이력서 원본, 공고, 리뷰 기록입니다. skill 폴더에는 사용자 자료가 들어가지 않으므로 `git pull`로 업데이트하면 됩니다.

## 검사

원고의 기계적 교열 오류를 찾습니다. 공백 두 칸, 굵은 글씨 안의 콜론, 괄호 짝, 표기 혼용, 기간 표기, 서술형 불릿을 봅니다.

```bash
node scripts/check-copy.mjs <원고 파일>
node scripts/check-copy.mjs --terms my-terms.json <원고 파일>
node --test scripts/*.test.mjs
```

Node 20 이상이 필요하며 다른 의존성은 없습니다. 마크다운과 HTML 원고를 모두 읽습니다.

## 구성

| 경로 | 역할 |
| --- | --- |
| `rules/` | 고정. 모드 판정, 근거 수집, 문장, 표기, 리뷰, 맞춤본, 렌더 점검 |
| `adapters/` | 교체. 이력서 형식별 읽기·편집·렌더 요령 (markdown, pdf, notion, rxresume) |
| `templates/` | 설정(workspace), 경력 사실, 리뷰 보고 양식. 처음 실행 때 `home`으로 복사됩니다 |
| `scripts/` | 교열 검사와 테스트 |

개인 정보는 이 저장소에 두지 않습니다. 모든 사용자 자료는 `home`에 둡니다.
